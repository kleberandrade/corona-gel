# Corona Gel v2.0.0

Modernized Java/Swing kiosk and timed dispenser controller for Raspberry Pi 3B.
This major release replaces the Java 8 / Pi4J 1.x / NetBeans distribution.

## Download

Use `corona-gel-2.0.0-linux-arm64.tar.gz` plus `SHA256SUMS` from this release.
The archive includes the compiled JAR, required `lib/` dependencies and their
notices, illustrated portrait demo media, launcher, autostart helper and README.
The automatic GitHub source archives are source code, not the prebuilt application.

```sh
sha256sum -c SHA256SUMS
tar -xzf corona-gel-2.0.0-linux-arm64.tar.gz
cd corona-gel-2.0.0
./run.sh
```

The first run is simulation, inside a graphical desktop session. Java 21 with
`java.desktop` must already be installed; the archive does not bundle a JVM.
Keep `lib/` beside `corona-gel.jar`. See the included `README.txt` before enabling
hardware or configuring autostart. No build or Maven is required to run the archive.

## Changes

- Java 21, Pi4J 3.0.4 and pinned Maven Wrapper/toolchain; no committed snapshot JARs
  or machine-specific IDE/library paths.
- Testable timing policy, 50 ms stability filtering, one 1.5-second pulse followed
  by 4-second cooldown, fresh-release requirement and off/close attempts on failures.
- Raspberry Pi 3B BCM17 active-low sensor / BCM27 active-high driver contract retained.
- Simulation by default, explicit real-GPIO activation, deterministic console example.
- Robust image discovery, Swing scheduling fixes, illustrated portrait/landscape
  demo slides and reproducible real-component screen previews.
- Optional reversible Labwc desktop autostart with hardware enabled, selected Java
  21, logs and a single-instance lock for automatic launches.
- English installation/migration/relay wiring guides, editable circuits, MIT license
  for original work and preserved third-party notices.
- Linux x64 and ARM64 CI plus release packaging/checksum verification.

## Requirements and migration

Target: Raspberry Pi 3B, 64-bit Raspberry Pi OS Desktop, Java 21, GPIO permissions
and the reviewed sensor/relay interface. Trixie is the documented APT setup;
Bookworm users need the separately documented ARM64 JDK 21 installation.
An unchanged 2020 Java 8/Raspbian/WiringPi installation is not supported by this build.

Back up media and old startup configuration. Extract to a new directory, copy your
media and stop the previous process before switching. If autostart was enabled,
re-run its helper with the new installation's `--app-dir`. Do not mix old/new JARs.

## Validation and limits

The release workflow builds and tests on Linux ARM64, verifies the archive/checksum
and runs the console example from the extracted distribution before publishing.
The same release-packaging smoke check runs in main CI on Linux x64 and ARM64.
Software tests cover the controller, Swing behavior, autostart using fake Java and
archive contents/reproducibility. Dependency JARs retain their notices unchanged.

No physical Raspberry Pi boot, GPIO/relay/pump, electrical load, interactive desktop,
fluid compatibility, sanitation or clinical validation has been performed here.
Timing relies on a functioning JVM/native backend and Linux scheduling; it is not a
hard real-time hardware cutoff. Initially test with the pump disconnected and follow
the documented power/driver requirements. The totem image is an illustrative concept.
